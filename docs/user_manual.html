Quest Hub ユーザーマニュアル

Mac 1台で最大50台の Meta Quest 3 を表示・録画・管理するためのアプリです。このマニュアルでは、授業や研究室で使うときの操作手順を説明します。

1. 概要と構成

Quest Hub は Mac で動くローカルの Web アプリです。管理画面は Chrome のアプリウィンドウとして開きます。次のことをブラウザから操作できます。

  • Quest の Wi-Fi 経由のデバッグ（ADB）を有効にする
  • 端末の IP アドレス・接続先 SSID・電池残量を記録する（端末台帳）
  • 最大50台の画面を一覧で表示し、1台を拡大して音声を聞く
  • 映像と音声を録画する
  • PC・Android・iPad のブラウザ向けに、閲覧専用のビューワーを公開する
  • キー入力・タップ・文字入力を送る

管理画面は Mac 本体でだけ開けます（127.0.0.1）。ほかの端末には、閲覧専用のビューワーを公開します。ビューワーからは操作できません。端末の IP や SSID も表示しません。

2. 動作環境

項目要件
MacmacOS 13（Ventura）以降。Apple Silicon・Intel のどちらでも動作します。50台を扱う場合は、Mac を有線 LAN でつなぐことを推奨します。
ブラウザ（管理画面）Google Chrome を推奨します。Chrome がない場合は既定のブラウザで開きます（WebCodecs 対応が必要です）。
QuestMeta Quest 3。開発者モードを有効にし、初回だけ USB ケーブルで Mac に接続します。
ネットワークQuest と Mac が同じ LAN にあり、互いに通信できること（端末どうしの通信を遮断するゲスト隔離が無効であること）。Wi-Fi 6 / 6E・5GHz 以上を推奨します。
閲覧用の端末Chrome・Edge（PC・Android）、Safari（Mac・iPad / iPhone、iPadOS 16.4 以降）。最初に1回、証明書の導入が必要です。
その他Homebrew・conda・Xcode Command Line Tools は不要です。インストーラーがリポジトリ内に必要なものを用意します。

3. インストール

ターミナルでリポジトリのフォルダに移動し、次を実行します。管理者権限（sudo）は不要で、シェルの設定も変更しません。

./install.sh            # 初回インストール。更新後の再実行も可
./install.sh --doctor   # 環境チェックだけを行う

インストーラーは、チェックサムを検証した micromamba を .tools/ に置き、Python 環境・adb・scrcpy 5.0.1 を .mamba-env/ に入れます。最後に環境チェック（--doctor と同じ）を行います。

環境チェック（--doctor）で確認する項目

  • micromamba、Python と必要なモジュール（av、fastapi、uvicorn、cryptography、qrcode、requests）
  • adb、scrcpy（5.0.1 であること）
  • Google Chrome（見つからない場合は警告）
  • 使用するポート

FAIL が出た場合は、./install.sh をもう一度実行してください。

その他のオプション

オプション用途
--strictlock ファイルと固定版の platform-tools だけでインストールします。授業用の Mac を同じ構成にそろえたいときに使います。
--build-from-sourcescrcpy をソースからビルドします（Xcode Command Line Tools が必要です）。通常は不要です。
--relock [osx-arm64|osx-64]依存関係を解決し直して lock ファイルを書き換えます（保守担当者向け）。
--uninstall --yes.tools/ と .mamba-env/ を削除します。
--uninstall --purge-data --yes上に加えて、台帳・設定・証明書（~/.questhub）も削除します。

macOS 15 以降の「ローカルネットワーク」許可：初めて Quest に接続するとき、ターミナルアプリに対してローカルネットワークへのアクセス許可が求められます。許可しないと接続が No route to host で失敗します。拒否してしまった場合は、システム設定 ＞ プライバシーとセキュリティ ＞ ローカルネットワーク で許可してください。

4. 起動と停止

起動

Finder で questhub.command をダブルクリックするか、ターミナルで次を実行します。

./questhub.command

Chrome のアプリウィンドウで管理画面（http://127.0.0.1:8765/）が開きます。ウィンドウを閉じてしまった場合は、Chrome でこの URL を開いてください。

起動オプション内容
--port 番号管理画面のポートを変更します（既定 8765）。
--no-browser管理画面のウィンドウを自動で開きません。
--data-dir パスデータの保存先を変更します（既定 ~/.questhub）。
-v詳しいログを表示します。

すでに起動している場合は、2つ目は起動せず、既存の管理画面を開きます。

停止

起動したターミナルで Ctrl+C を押します。録画中のファイルは正しく閉じられます。授業の後は、先に管理画面の 授業を終了 を使うことを推奨します（14章）。

5. 初回準備

5.1 開発者モードと USB デバッグ

  1. スマートフォンの Meta Horizon アプリで、ヘッドセットの開発者モードを有効にします。
  2. Quest を USB ケーブルで Mac に接続します。
  3. ヘッドセット内に「USB デバッグを許可しますか？」と表示されたら、「常に許可」を選びます。

5.2 Wi-Fi 化（管理画面の「端末」タブ）

  1. 端末 タブを開きます。「USB 接続の端末」に接続中の Quest が表示されます。
  2. 対象にチェックを入れて 選択した端末を Wi-Fi 化、または USB 端末をすべて Wi-Fi 化 を押します。
  3. 「Wi-Fi 化しました（IP / SSID）」と通知されたら、USB ケーブルを抜いて構いません。IP と SSID は台帳に記録されます。

表示されるラベルの意味は次のとおりです。

  • USB：USB で接続中です。
  • Wi-Fi 済み：すでに Wi-Fi 化されています。
  • ヘッドセット内で USB デバッグを許可してください：5.1 の許可がまだです。

Wi-Fi ADB は、Quest を再起動すると無効になることがあります。その場合、接続状態が USB で再有効化が必要 になります。もう一度 USB でつないで Wi-Fi 化してください。IP の変化を防ぐため、ルーターの DHCP 予約で端末ごとに IP を固定しておくと運用が楽になります。

5.3 LAN のスキャン

すでに Wi-Fi 化した端末は、「LAN をスキャン」の スキャン で探して台帳に登録できます。範囲を空欄にすると、この Mac のサブネットを調べます。192.168.10.0/24 のように指定することもできます。

5.4 端末台帳

端末タブの表で、端末ごとに次の項目を確認・編集できます。名前・IP・席・品質はその場で書き換えると保存されます。

列内容
名前表示名（例：Quest-01、座席番号）。タイル・録画ファイル名に使われます。
接続Wi-Fi USB 許可待ち 接続中 オフライン USB で再有効化が必要
IP手で入力した IP には 固定 が付き、スキャンで上書きされません。
Wi-FiSSID・帯域・電波強度（dBm）
電池残量（%）。充電中は ⚡ が付きます。
席(列,行)モニター画面での位置（0 から数えます）。空欄なら自動で並べます。
品質端末ごとの品質（7章）
表示ストリームの状態と、REC（録画中）・黒画面 の表示
操作接続/切断、表示/表示停止、削除（台帳から削除）

5.5 TSV の読み込み・書き出し

「端末リスト（TSV）」の 書き出し と 読み込み で、CLI と同じ scripts/quest_devices.tsv 形式の台帳をやり取りできます。形式はタブ区切りで、名前　IP:ポート　[列]　[行] です。

# alias	endpoint	[col]	[row]
Quest-01	192.168.10.21:5555
Quest-02	192.168.10.22:5555	1	0

読み込んだ端末は、まだ接続していなければ名前の下に「TSV（未接続）」と表示されます。初めて接続した時点で、本来の端末情報に統合されます。SSID などの Wi-Fi 情報は TSV に含まれません（12章の CSV を使ってください）。

6. 画面の見方

上部のタブで画面を切り替えます。右上には「接続 ○/○ · 表示 ○ · 録画 ○ · ビューワー公開中（○人）」の概要が出ます。

タブ内容
モニター表示中の全端末のグリッド、一括操作
端末Wi-Fi 化、LAN スキャン、TSV、端末台帳
録画録画の開始・停止、録画中の一覧、過去のセッション
ネットワークSSID の変更警告、SSID / アクセスポイント / 帯域ごとの台数。未確認の警告があると、タブに件数が出ます。
設定・ビューワービューワーの公開、既定値、授業の終了

6.1 モニター（グリッド）

  • 全台表示：接続中の全端末の表示を始めます。全台停止：すべての表示を止めます（録画中の端末があると止まりません）。
  • 全台の品質：全端末の品質を一度に変えます（録画中の端末は除きます）。
  • 表示：「全フレーム」か「キーフレームのみ（低fps）」を選びます。台数が多くて Mac が重いときは低fps にします。
  • 列：グリッドの列数。「自動」は台数に合わせます。
  • タイルをドラッグすると、座席（並び順）を入れ替えられます。
  • 表示が追いつかないタイルは、自動で低fps に切り替わります（「表示が追いつかないため低fpsに切り替えました」と通知）。しきい値は設定の「自動で低fpsにする閾値（fps）」です。

「接続したら自動で表示」が有効（既定）なら、Quest が接続されると自動で表示が始まります。

表示意味

!SSID の変更などの警告があります（ネットワークタブで確認）

6.3 拡大表示

タイルをクリックすると、その端末を大きく表示します。右側のボタンは次のとおりです。

ボタン内容

品質この端末の品質を変えます
キーフレーム要求映像が乱れたときに、すぐ新しい完全なフレームを送らせます
ネイティブ表示scrcpy のウィンドウで開きます。キーボード・マウスで細かく操作したいときに使います（10章）
黒画面の診断Quest の表示状態を記録し、推定原因を通知します（13章）
「画面クリックで操作」、BACK / HOME / WAKE / MENU、文字入力入力操作（10章）
閉じるグリッドに戻ります

上部には状態・解像度・fps・SSID が表示されます。

7. 品質プリセットと帯域の目安

品質は3段階から選びます。既定は「標準」です。設定の「既定の品質」、端末ごとの「品質」、モニターの「全台の品質」で変更できます。

プリセット長辺fps映像1台あたり10台30台50台
低（省帯域）960px151.5 Mbps約1.68 Mbps16.8 Mbps50.4 Mbps84 Mbps
標準1280px304 Mbps約4.25 Mbps42.5 Mbps127.5 Mbps212.5 Mbps
高（詳細）1920px6010 Mbps約10.43 Mbps104.3 Mbps312.9 Mbps521.5 Mbps

帯域は計画用の上限の目安です（映像の上限 + 音声 0.128 Mbps + 通信の余分 約3%）。動きの少ないメニュー画面では、これよりずっと少なくなります（実測で標準は約 0.6 Mbps）。

選び方の目安

  • 50台を1つのネットワークで扱う → 「低」または「標準」。アクセスポイントを複数台に分け、Mac は有線 LAN で接続します。
  • 特定の数台を詳しく見たい → その端末だけ「高」にします。
  • 録画の画質も同じ品質になります。録画中は品質を変更できません。

品質を変えると、その端末のストリームが1秒ほど途切れてから再開します（状態は「品質変更中」）。

8. 音声

  • 音声は Quest の再生音（Opus、128kbps）を取得します。設定「音声を取得」で無効にできます。
  • 「ヘッドセットの音も残す（audio_dup）」が有効（既定）なら、Quest のスピーカーからも音が出たままになります。
  • Mac で聞けるのは、拡大表示中の1台だけです。拡大表示の 音声を再生 を押してください（ブラウザの仕様で、クリックしないと再生できません）。
  • 録画には、表示していない端末も含めて音声が入ります。
  • 端末が音声の取得に対応していない場合は、映像だけで表示し、警告を出します。

9. 録画

9.1 開始と停止（「録画」タブ）

  1. セッション名を入力します（例：2026-11-lesson01）。空欄なら日時になります。
  2. 表示中の全台を録画、または一覧で端末を選んで 選択した端末を録画 を押します。
  3. 止めるときは すべて停止、または「録画中」の表の各行の 停止 で個別に止めます。

録画できるのは表示中の端末です。「録画中」の表には、経過時間・サイズ・分割数・ファイル名が出ます。「過去のセッション」には、これまでの録画の一覧が出ます。

9.2 保存場所とファイル

recordings/<セッション名>/
  <名前>_<シリアル末尾6桁>_<YYYYmmdd-HHMMSS>.mkv
  <名前>_<シリアル末尾6桁>_<YYYYmmdd-HHMMSS>_part02.mkv   ← 分割されたとき
  session.json                                                ← 端末・IP・SSID・時刻の記録
  • 保存先は設定「録画の保存先」で変更できます（既定はリポジトリの recordings/）。
  • 形式は MKV（映像 H.264 + 音声 Opus）です。再エンコードせず、届いたデータをそのまま保存します。VLC などで再生できます。
  • 同じセッション名がすでにある場合は、名前_2 のように新しいフォルダを作ります。以前の録画は上書きしません。
  • 接続が途切れて再接続しても、同じファイルに続けて書きます。
  • パート分割：解像度や映像の設定が変わったとき（品質の変更、Quest 側の画面サイズの変化など）は、_part02、_part03 … の新しいファイルに続けて書きます。

9.3 録画中の制限

  • 録画中の端末は、品質の変更・表示停止・切断・全台停止・ネイティブ表示ができません（録画が気づかないうちに途切れないようにするため）。先に録画を止めてください。
  • 空き容量が「録画を止める空き容量（GB）」（既定 5GB）を下回ると、自動で録画を止めて通知します。

50台を「標準」で録画すると、最大で毎時およそ 95GB になります（212.5 Mbps × 3600 秒 ÷ 8）。実際は画面の動きに応じて少なくなりますが、空き容量に余裕を持たせてください。

10. 入力操作

10.1 一括操作（モニター）

モニターの「一括:」にある HOME BACK WAKE を押すと、表示中の全端末に同じキーを送ります。

10.2 1台の操作（拡大表示）

  • 「画面クリックで操作」にチェックを入れると、映像をクリック・ドラッグした位置にタッチを送ります。
  • BACK HOME WAKE MENU：キーを送ります。
  • 文字入力欄に入力して 送信：文字を入力します（テキスト欄にフォーカスがあるとき）。

VR の 3D 画面では、タップが効かないことがあります。その場合は ネイティブ表示 で scrcpy のウィンドウを開いて操作してください。ネイティブ表示の間、その端末の Quest Hub 側のキャプチャは一時停止し（「ネイティブ表示中」）、ウィンドウを閉じると再開します。ネイティブ表示では音声は出ません。

ビューワー（閲覧用の端末）からは操作できません。

11. ブラウザビューワー

PC・Android・iPad などのブラウザで、表示中の端末を閲覧できます。一覧は低fps（キーフレームのみ）で表示して負荷を抑えます。タイルをクリックすると、その1台をフレームレートを落とさずに表示し、音声も再生できます。

11.1 公開する

  1. 設定・ビューワー タブで「ビューワーを公開する」をオンにします。
  2. 6桁の アクセスコード、URL（https://<Mac の IP>:8443/）、QR コード（ビューワー・証明書の導入ページ）が表示されます。
  3. 閲覧する人に QR コードか URL とアクセスコードを伝えます。
  • 変更（全員ログアウト）：アクセスコードを変更し、ログイン中の全員をログアウトさせます。
  • 右上の「ビューワー公開中（○人）」で視聴者数が分かります。
  • 拡大表示できるのは、視聴者1人につき1台、全体で8台までです。
  • ビューワーには端末の IP・SSID は表示されません。

11.2 証明書の導入（閲覧する端末ごとに1回）

ビューワーは HTTPS で通信します。Quest Hub は最初にこの Mac 専用の証明書（Quest Hub Local CA）を作ります。閲覧する端末は、その証明書を信頼済みとして1回だけ登録します。証明書の導入ページ（http://<Mac の IP>:8766/、QR あり）を開き、手順に従ってください。

iPad / iPhone（Safari）

  1. 「構成プロファイルをダウンロード」を押し、「許可」を選ぶ
  2. 設定アプリ ＞「プロファイルがダウンロードされました」＞ インストール
  3. 設定 ＞ 一般 ＞ 情報 ＞ 証明書信頼設定 で「Quest Hub Local CA」をオン

Android（Chrome）

  1. 「CA 証明書をダウンロード」を押す
  2. 設定 ＞ セキュリティ ＞ 暗号化と認証情報 ＞ 証明書のインストール ＞ CA 証明書
  3. ダウンロードした QuestHubLocalCA.crt を選ぶ

Mac（Chrome / Safari）

  1. 証明書をダウンロードして開き、キーチェーン「ログイン」に追加
  2. キーチェーンアクセスで「Quest Hub Local CA」を開き、「信頼」＞「常に信頼」

Windows（Chrome / Edge）

  1. 証明書（.cer）をダウンロードして開き、「証明書のインストール」
  2. 「証明書をすべて次のストアに配置する」＞「信頼されたルート証明機関」

導入前に、ページに表示される指紋（SHA-256）が管理画面の「指紋」と同じであることを確認してください。違う場合は導入しないでください。

11.3 閲覧する

  1. ビューワーの URL を開き、アクセスコード（6桁）を入力して 開く を押します。
  2. 一覧が表示されます。列 で列数を変えられます。
  3. タイルをクリックすると拡大表示します。音声を再生 で音が出ます。
  4. 終わったら ログアウト を押します。

「このブラウザは WebCodecs（映像デコード）に対応していないか…」と出る場合は、ブラウザを最新版にするか、証明書の導入と HTTPS での接続を確認してください。

12. SSID の変更警告

  • どの SSID でも動作します。端末ごとに SSID が違っても構いません。
  • 端末が接続したときの SSID を基準にし、稼働中に SSID が変わると警告します（通知、タイルの !、ネットワークタブの件数）。
  • Wi-Fi 情報が読めなくなった場合も「Wi-Fi情報を取得できません」と警告します。
  • 警告はネットワークタブで 確認 を押すまで残ります。確認すると、その時点の SSID が新しい基準になります。

ネットワークタブでは、SSID・アクセスポイント（BSSID）・帯域ごとの台数が分かります。電波が弱い（-70dBm 未満）端末と、2.4GHz で接続している端末も表示します。1台のアクセスポイントに端末が偏っていないか、授業前に確認してください。Wi-Fi 情報を CSV で書き出し で一覧を保存できます。

Wi-Fi 情報は「計測間隔（秒）」（既定 60 秒）ごとに更新します。電池残量も同じ間隔です。

13. 黒画面の検出・復旧・診断

Quest では、エラーが出ないまま映像だけが真っ黒になることがあります。Quest の画面キャプチャは、Meta のコンポジター（VR の映像を合成する仕組み）の「録画」を経由しています。そのため、コンポジターが録画先に描画しない状態になると黒くなります。

装着中のテストでは、Meta ボタンのメニューを開いたときと、ブラウザなどのアプリを起動した直後に、10〜20秒ほど黒くなりました。これは Meta が意図的に録画を止めているもので、毎回自然に戻ります。授業では、この間は映像が途切れることを講師・TA に伝えておいてください。クイック設定や設定アプリの表示中は黒くなりませんでした。

13.1 主な原因

原因対処
Meta が一時的に録画を止めている（メニューを開いた・アプリの起動直後）10〜20秒ほどで自然に戻ります。この間、Quest Hub は復旧を行わずに待ちます（確認済み）
ヘッドセットを装着していない（近接センサー）自動復旧で「装着中」扱いにすると戻ります（確認済み）
スリープ・画面オフ自動復旧で画面を起こします
保護されたレイヤーの表示中Meta が録画を禁止しているため戻りません
画面の切り替え中などキャプチャの作り直しやサーバーの再起動で戻ることがあります

13.2 Quest Hub の動作

  1. 検出：映像がほぼ真っ黒の状態が3秒続くと黒画面と判定し、タイルと端末一覧に 黒画面 を表示し、推定原因を通知します。暗い場面を誤って判定しないよう、映像の明るい部分で判断します。
  2. 自動復旧：黒画面が続く間、次の順に試します（1分に1回まで繰り返します）。
    1. すぐに：キャプチャを作り直す
    2. 6秒後：画面を起こし、「装着中」扱いにする
    3. 12秒後：Quest 側のサーバーを再起動する
    映像が戻ると「映像が戻りました（キャプチャ再作成 / 画面の再起動 / サーバー再起動 で復旧）」と通知します。
    ただし、Meta が録画を止めている間は、これらを行わずに待ちます（効果がないため）。止まった状態が45秒を超えた場合や、止まった状態が終わっても黒いままの場合は、上の順に試します。
  3. 診断ログ：黒画面を検出すると、Quest の表示状態（コンポジター、前面のアプリ、電源、近接センサー、ディスプレイ）を ~/.questhub/diagnostics/black_<シリアル>_<日時>.txt に保存します。

黒いのに検出されない場合は、拡大表示の 黒画面の診断 を押してください。その時点の状態を manual_<シリアル>_<日時>.txt に記録し、推定原因を通知します。不具合の報告にはこのファイルを添えてください。

13.3 設定

  • 「黒画面（Quest 側）を検出する」
  • 「黒画面から自動で復旧を試みる」
  • 「復旧時に「装着中」扱いにする（prox_close）」

いずれも既定で有効です。ビューワーでも該当するタイルに「黒画面（Quest 側）」と表示します。

近接センサーの戻し忘れに注意

「装着中」扱い（prox_close）にしたヘッドセットは、元に戻すまで画面が消えず、自動スリープもしません。Quest Hub は、復旧でこれを使った端末を、表示停止・授業を終了・Quest Hub の終了時に自動で元に戻します。

Quest Hub が異常終了した場合や、CLI を使った場合は、次のコマンドで戻してください。

./scripts/quest_os_tweaks.sh restore

戻ったかどうかは、adb shell dumpsys vrpowermanager | grep 'proximity state' が DISABLED になっていることで確認できます。

14. 授業の流れのチェックリスト

前日まで

  • ./install.sh --doctor がすべて OK
  • 全台の開発者モードと「USB デバッグを常に許可」
  • 全台を Wi-Fi 化し、台帳に名前（座席番号）と席を登録
  • ルーターで DHCP 予約（IP 固定）
  • アクセスポイントを複数台用意し、台数を分散
  • 閲覧用の端末に証明書を導入
  • 録画の保存先の空き容量を確認

開始前（15分前）

  • Quest を充電（80% 以上）
  • ./questhub.command で起動
  • 端末タブで全台が Wi-Fi。オフラインの端末は Wi-Fi を入れ直す
  • ネットワークタブで SSID・アクセスポイントの偏り・電波の弱い端末を確認
  • 台数に合わせて品質を選ぶ（7章）
  • タイルの名前と座席表を照合
  • 必要ならビューワーを公開し、QR を投影

授業中

  • 録画タブでセッション名を付けて録画開始
  • 通知（SSID 変更、黒画面、ディスク不足）を確認
  • 重い場合は表示を「キーフレームのみ（低fps）」に
  • SSID 警告は原因を確認してから 確認

終了時

  • 設定・ビューワー ＞ 授業を終了（録画停止・ビューワー停止・表示停止）
  • 端末を持ち出す場合は「全端末の Wi-Fi ADB を無効化する」にチェック（次回は USB 接続が必要）
  • 録画タブの「過去のセッション」でファイルを確認
  • Ctrl+C で Quest Hub を終了

授業を終了 の後は、Quest が接続されても自動では表示しません。再開するときは 全台表示 か、端末ごとの 表示 を押してください。

16. CLI との関係

リポジトリには、scrcpy のウィンドウを1台ずつ並べる従来の CLI（scripts/quest_multi_scrcpy.sh など）も含まれています。使い方は agents.md と README.md にあります。

同じ端末に GUI と CLI を同時に使わないでください。1台のヘッドセットを2重にキャプチャすると、Quest の負荷が2倍になります。CLI は、Quest Hub の起動中に実行すると警告を出します。

  • 端末台帳は TSV（scripts/quest_devices.tsv）で共用できます（5.5）。
  • CLI の品質プリセット（--quality low|standard|high）は GUI と同じ値です。
  • CLI の --quest-tweaks で近接センサーを「装着中」にした場合は、終了後に ./scripts/quest_os_tweaks.sh restore で戻してください。
